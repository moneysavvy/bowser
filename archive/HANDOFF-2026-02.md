## Architecture

### Fast Build System

```
examples/
├── templates/
│   ├── base.html      # Shared dark-theme CSS + placeholders
│   ├── specs.json     # App definitions (id, title, max_width, prompt)
│   └── assemble.py    # Merges model JSON output into template
├── fast-build.sh      # Parallel build: spawns N claude -p calls
└── .build-logs/       # Raw model output, status, assemble logs
```

**Flow:**
1. `fast-build.sh` reads `specs.json`, spawns one `claude -p` per app in parallel
2. Each agent outputs JSON: `{ extra_head, app_styles, app_html, app_script }`
3. `assemble.py` injects into `base.html` placeholders
4. Output: `examples/<app-id>/index.html`

**Optimizations:**
- **Template/scaffolding** — 149 lines of shared CSS, model only outputs app logic
- **Parallel generation** — 5 apps in ~72s wall time vs ~5min sequential
- **Smaller context** — ~150-word prompt per app, no template CSS in context

### Model Configuration

- **Project:** `.claude/settings.json` → MiniMax-M2.5-highspeed
- **User:** `~/.claude/settings.json` → Anthropic (for fast mode in interactive TUI)
- **API keys:** `.env` (MINIMAX_API_KEY, ANTHROPIC_API_KEY)

### Vercel Deployment

- **Scope:** `tolas-projects-41ed0696`
- **Per-app:** `vercel.json` rewrites `/*` → `/index.html`
- **Manage:** `examples/manage.sh list|test|deploy [app]|delete <app|all>`

## How to Run

### Local (Live Server)

```bash
# From project root, serve examples/
# Use VS Code Live Server or:
cd examples && python3 -m http.server 5500
# Then open http://127.0.0.1:5500/01-todo-app/index.html
```

### Speed Test All Apps

```bash
cd bowser
bash examples/manage.sh test
```

### Rebuild Template Apps (06–10)

```bash
cd bowser
bash examples/fast-build.sh
# Optional: deploy after build
bash examples/fast-build.sh --deploy
```

### Deploy to Vercel

```bash
cd bowser/examples
bash manage.sh deploy          # all apps
bash manage.sh deploy 01-todo-app   # single app
```

## UI Review Notes

- **Dark theme:** Template-built apps (06–10) must use CSS variables (`--text-primary`, `--card-bg`, etc.). No `#fff` or white backgrounds — causes invisible text on dark gradient.
- **Specs enforcement:** `specs.json` prompts explicitly say "NO white backgrounds, NO light-mode colors."
- **Agent Dashboard:** Uses dark theme; all text has sufficient contrast.
- **Invoice Dashboard (15):** Light theme (business-facing); white/gray backgrounds with dark text.

---

## Known Limitations

1. **Fast build:** Requires `claude` CLI and `-p` (programmatic) mode. Fast mode is not available in SDK mode.
2. **Vercel:** Apps 06–15 may not be deployed yet; run `manage.sh deploy` to push.
3. **ChoiceHH original:** `file:///Users/.../choicehh-invoice-dashboard/dashboard/index_pro.html` uses external `js/api.js` and `js/dashboard_pro.js` — requires backend. The standalone `15-invoice-dashboard` uses mock data and works without a backend.
